# 纯文案时间轴估算规则

## 1. 核心限制

只有文案时无法知道真实语速、停顿、重录、剪掉的口头语和表情停留，因此不能产出“准确时间码”。所有时间码必须标注 `estimated`。

本 Skill 使用**双锚点时间轴**：

- 估算时间：帮助剪辑师快速定位大致位置；
- 文案锚点：确保即使估算漂移，也能在成片中准确找到切入和切出句子。

## 2. 三重定位字段

每个片段必须同时包含：

- `sentence_range` 或 `line_range`；
- `start_anchor`：片段开头 6–18 个字的稳定短语；
- `end_anchor`：片段结尾 6–18 个字的稳定短语；
- `start` / `end`：估算秒数；
- `spoken_text`：用于估时的完整原文，不得只放摘要。

锚点不要选择“然后、其实、所以、啊”这类高重复词，要选择能唯一定位的内容短语。

## 3. 速度档位

以下为内部启发式，可根据用户后续反馈校准：

| 档位 | 建议单位速度 | 常见文案 |
|---|---:|---|
| `reflective` | 3.6–4.0 单位/秒 | 情绪、故事、价值反思 |
| `standard-explanatory` | 4.0–4.5 单位/秒 | 教育解释、工具介绍 |
| `fast-punchy` | 4.6–5.2 单位/秒 | 短句、清单、节奏型内容 |
| `mixed` | 分阶段设置 | 钩子快、案例中速、结尾慢 |

“单位”不是字符数的简单等价：

- 一个汉字约 1 单位；
- 一个英文单词约 2.2 单位；
- 一个数字串约 2 单位；
- 逗号、顿号、换行和句号增加不同程度的停顿单位；
- 长产品名、公式、网址和专业术语可额外增加时长。

## 4. 估算流程

1. 保留口头填充词，因为真实口播通常会说出来；
2. 按语义片段统计发音单位；
3. 根据本篇节奏档位计算基础时长；
4. 在段落切换、编号、反问和情绪句前后增加停顿；
5. 将片段连续排列，生成 0.5 秒精度的时间轴；
6. 给项目级总时长提供一个范围，默认误差带约 ±8%–15%；
7. 若用户给出计划总时长，则按比例缩放片段，但不改变语义边界；
8. 若用户后来提供个人平均语速，优先使用其历史值。

## 5. 可执行脚本

使用 `spoken_text` 重算所有片段：

```bash
python scripts/recalculate_estimated_timecodes.py visual-plan.json --pace 4.1
```

常用参数：

```bash
# 更慢的教育反思口播
python scripts/recalculate_estimated_timecodes.py visual-plan.json --pace 3.8

# 更快的清单型口播
python scripts/recalculate_estimated_timecodes.py visual-plan.json --pace 4.8

# 用户预期成片为 180 秒，按比例缩放
python scripts/recalculate_estimated_timecodes.py visual-plan.json --target-duration 180
```

脚本会更新 `start`、`end`、`duration_seconds`、`duration_range_seconds` 和项目级速度记录。

## 6. 剪辑显示格式

HTML 与 CSV 应把以下信息放在同一区域：

```text
S06｜01:12.0–01:22.5（估算）
开始锚点：“第二个建议是”
结束锚点：“先把它在本地跑起来”
原文定位：P08-S01 ～ P09-S02
```

## 7. 不合格情况

- 只有秒数，没有文案锚点；
- 把估算时间写成精确到帧；
- 用摘要而不是完整口播文字估时；
- 每句平均分配相同时间；
- 忽略英文产品名、数字和自然停顿；
- 未声明真实成片需要重新对齐。
