# 每篇脚本动态分析框架

## 1. 原则

任何视觉建议之前，先把当前文案当作一个独立作品建立“本篇脚本画像”。固定创作者画像只是先验，不得覆盖文案本身的证据。

## 2. 必须输出的脚本诊断

### 核心命题

用一句话说明：观众看完后应该相信、理解或去做什么。

### 内容原型

从下列原型中选择 1–3 个，并标注主次：

| 原型 | 特征 | 默认视觉侧重 |
|---|---|---|
| `opinion` 观点判断 | 明确主张、反常识、价值判断 | 人物、关键词、证据卡，少用泛化B-roll |
| `tool-recommendation` 工具推荐 | 产品能力、适用人群、成本、替代方案 | 真实界面、对比卡、操作结果 |
| `tutorial` 教程操作 | 步骤、按钮、输入输出、错误处理 | 真实录屏为主，图形辅助 |
| `method-list` 方法清单 | 一二三结构、框架、行动步骤 | 编号卡、流程图、每项一个代表画面 |
| `case-study` 项目案例 | 背景、行动、障碍、结果、复盘 | 真实证据、过程镜头、前后对比 |
| `story` 故事叙述 | 人物、场景、冲突、转折 | 情境B-roll、物体特写、适度保留人物 |
| `news-explainer` 新闻解读 | 新事件、来源、影响、判断 | 来源截图、时间线、数据和引用卡 |
| `concept-explainer` 概念解释 | 抽象定义、因果、类比 | 图示、类比物体、简洁动画 |
| `reflection` 经验反思 | 个人经历、感受、价值上升 | 人物为主，少量克制情绪镜头 |
| `call-to-action` 行动号召 | 明确要求观众尝试、收藏、评论 | 人物、短字卡，不再引入新信息 |

### 本篇受众侧重

判断 `parent-first`、`ai-user-first` 或 `balanced`，并说明依据：

- 是否大量讨论孩子、家庭、教育成本、家长顾虑；
- 是否大量讨论模型、Agent、工作流、界面、部署或效率；
- 哪一类观众是本篇的第一行动者；
- 术语是否需要翻译成生活语言。

### 论证结构

将整篇拆成 4–8 个阶段，例如：

`钩子 → 观众顾虑 → 证据/例子 → 方法 → 结果 → 价值升华 → CTA`

每个阶段记录原文范围、传播任务和视觉任务。

### 情绪曲线

从以下词中选取并按顺序排列：

`好奇`、`紧迫`、`担心`、`理解`、`释然`、`惊喜`、`可信`、`兴奋`、`受鼓舞`、`行动意愿`。

视觉节奏应服务情绪变化，不得全片保持同一强度。

### 信息与证据维度

分别判断：

- 信息密度：`low / medium / high`；
- 抽象程度：`low / medium / high`；
- 证明需求：`low / medium / high`；
- 操作性：`low / medium / high`；
- 故事性：`low / medium / high`；
- 事实时效风险：`low / medium / high`。

### 口播节奏

选择：

- `reflective`：观点、故事、教育反思，建议较慢；
- `standard-explanatory`：常规知识解释；
- `fast-punchy`：短句密集、清单、强钩子；
- `mixed`：不同阶段速度明显变化。

给出估算单位速度和总时长范围。单位速度只是时间轴启发式，不是对真实成片的承诺。

### 全片视觉策略

必须动态给出：

- A-roll 目标占比；
- 建议视觉密度；
- 首 20–30 秒的视觉策略；
- 中段解释/证明策略；
- 结尾人物保留策略；
- 真实录屏、图形、图片、视频各自的预期用途；
- 3–6 个“本片关键视觉锚点”；
- 2–5 个“本片明确不应视觉化的句子或阶段”。

## 3. 受众侧重如何改变画面

### `parent-first`

- 先展示生活场景、成本、孩子行为和可执行结果；
- 技术界面只展示关键部分，并配通俗标签；
- 流程图不超过 3–5 个节点；
- 少用长时间终端和密集代码；
- 更重视信任、风险、门槛和结果。

### `ai-user-first`

- 增加真实界面、输入输出、流程和限制；
- 可使用更短、更密集的画面变化；
- 允许出现必要术语，但需突出关键步骤；
- 证据应具体到任务、输入、输出和对比；
- 避免只用“家长和孩子看电脑”的泛场景替代技术内容。

### `balanced`

- 一个技术证据后尽快连接一个生活或教育意义；
- 同一片段可采用人物 + 小尺寸真实界面的组合；
- 术语首次出现时解释，后续可简化；
- 视觉上交替使用真实操作、图形解释和人物信任锚点。

## 4. 节奏策略示例

### 工具教程型

开头人物承诺结果 → 快速展示成品 → 真实录屏分步骤 → 错误/限制 → 回到人物总结。

### 教育观点型

开头保留人物 → 关键概念用图示 → 家长顾虑用生活化画中画 → 案例用具体场景 → 结尾人物升华。

### 新闻解读型

开头人物概括事件 → 来源与日期卡 → 时间线/影响图 → 个人判断回到人物 → CTA。

### 项目案例型

结果先行 → 背景与问题 → 过程证据 → Bug/转折 → 成品前后对比 → 复盘。

这些只是视觉语法示例，不能把其中的具体素材硬套到新文案。

## 5. 失败判定

出现以下任一情况，说明没有真正做动态分析：

- 不论文案类型都给出相同 A-roll 比例；
- 不论受众侧重都建议同样多的技术录屏；
- 新文案没有相关内容，却仍出现 Codex、GitHub、PBL、孩子或机器人；
- 只按关键词找图，没有识别论证阶段；
- 没有说明为什么某些句子应保留人物；
- 每个段落都强行安排外部素材；
- 时间轴没有原文双锚点，剪辑者只能依赖估算秒数。
